# 离线阅读目录与排版 — 开发设计评审

## 评审结论

**设计充分性通过，可生成执行计划。** 三项功能复用既有设置、存储和排版路径，未引入新服务或架构。最高风险是倒序显示与原始章节索引混用，以及字重/段距未同步进入测量；设计已给出对应的映射和验证安排。本结论是代理设计检查，不表示用户逐项审阅或运行验收通过。

## 业务和技术主线

用户在阅读设置改变排版，控件先显示预览，保存成功后才由全局设置驱动正文重排；失败恢复已保存值。重排保留内容锚点，而非依赖屏幕页码。

目录按钮只改变显示顺序，项目选择始终映射回领域章节索引。独立目录组件承载当前确实存在的异步保存与关闭生命周期，不增加通用排序框架。方案比较见设计第一部分。

## 数据模型评审

### 完整字段定义

| 字段 | 类型 | 必填/空值 | 默认值 | 关联/约束 | 设计依据 |
| --- | --- | --- | --- | --- | --- |
| paragraphSpacing | double | JSON 可缺失 | 20 | 0–40；非数值/非有限值回退 20，copyWith 与读取保持边界 | D-002/D-003 |
| boldText | bool | JSON 可缺失 | false | 只把 JSON true 解释为开启，其他类型回退关闭 | D-002/D-004 |
| tocDescending | bool | JSON 可缺失 | false | 默认正序；只影响展示 | D-002/D-005 |

### 物理存储、继承与重复存储

现有 `meta/settings` 单键 JSON 承载偏好；无 ORM 基类、继承字段、软删除或新增关系。不复制章节和正文。已知键读取/覆盖是完整访问路径，无需二级索引或 migration。依据为设计“存储、继承与访问路径”。

### 字段与存储取舍

继续在同一设置对象中保存小标量，比新增每书覆盖层更直接；设计没有按书覆盖需求。降级版本可忽略新键，但降级后再次保存会使新偏好回默认，不影响原文与进度。

## 状态、并发和执行流程

重点检查保存中的重复提交禁用、保存失败的预览/目录回退，以及弹层关闭后的 mounted 防护。目录排序不得走正文排版重置通道；保存回调需读取 controller 最新设置以保留其他字段。依据为设计“状态、并发与执行流程”。

## 接口、权限和旧入口隔离

新增目录组件回调中的索引仍是原始章节索引；切章继续走现有 `_jump` 保存保护。网络与书源边界不动，不增加路由或权限。依据为设计“接口、权限与兼容边界”。

## 前端方案

控件来源为现有 Slider、Material 开关和目录按钮；设置保持可滚动、目录保持有界列表。预览使用现有段落组件，便于同时观察段距和字重。新增参数是产品选择，颜色与既有间距来自当前页面，不自行建立设计系统。具体映射与唯一视觉检查 owner 在 `design/frontend.md#前端设计`。

## 主要风险、迁移、发布和验证

### 主要风险

- 倒序后选错章节：标题、选中态、缓存标记与回调统一使用原始索引。
- 粗体或段距导致溢出/跳字：同步 style、paginator 参数及 layout key，并检查长段完整性。
- 旧数据字段缺失或损坏：默认与有限值约束，增加领域和实际仓储往返测试。
- 保存失败或弹层关闭后迟到完成：恢复已保存偏好并检查 mounted，不制造虚假的保存成功。

设计无本轮承诺范围内的延后项；历史双源验收缺口保持独立，不作为本轮成功证据。

### 迁移与发布

无 schema/data migration。分别构建和报告 Web/Android 产物，旧版本忽略新键。回滚不清理用户数据；异常恢复检查在完成或明确阻塞时停用。依据为设计“风险、迁移、发布、回滚与监控”。

## 评审顺序与抽查路径

1. 先检查原始索引映射和设置存储边界，避免产生数据含义变化。
2. 再检查 style、段距和 layout key 的一致性，以及偏好保存失败语义。
3. 最后按 Visual Checks 和验证方案核对真实页面与回归结果。

建议抽查路径：`ReaderTocSheet`、`ReaderSettings`、`ReaderScreen`、`ReaderPreferences` 及对应测试；均来自设计“核心对象与职责”和“验证方案”。
