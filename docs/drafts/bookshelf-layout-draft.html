书架布局草稿参考微信读书 · read-pilot

微信读书的书架不是「一屏平铺所有书」，而是两层：第一层按分组卡片排（每张卡是组内前 4 本书的封面拼图）， 点进去才是组内的书。这样书架再大也不会失控。read-pilot 现在把所有控件（继续阅读卡、搜索、在读/已读、分组 chips、 排序下拉、书籍网格）全部堆在同一个滚动流里，首屏被控件占满，一本书都要往下滑才看得见。

三、逐块对照 哪些照搬、哪些改动、哪些做不了

区块微信读书本草案说明
顶部搜索 胶囊搜索框，右侧「书城」跳书城 同款胶囊 + 右侧「书城」 「书城」映射到我们已有的发现页（nav 第 2 个 tab）。省掉一行 38px 的搜索框。
标题行 「书架」+ ⊕导入 + ✓选择 同款，22px 标题 去掉现在的 30px 大标题 + 副标题「把时间，留给好书。」（占了 60px 却零信息），导入从圆形 FAB 改成文字按钮。
排序行 默认 / 更新(19) / 进度 / 推荐值 / 书名 / 分类 默认 / 进度 / 书名 / 分类 横向纯文字 tab 取代现在的「全部·在读·已读」chips + 独立排序下拉。合并了两处冗余：现在的 3 个 chips 只筛状态、下拉只管排序，一行就够。
书架主体 分组卡片网格（3 列，2×2 封面拼图） 同款；不足 4 本按第二节补白 这是核心改动：从「平铺所有书」变成「先看分组」。组卡下方补一行「N 本」，因为微信读书靠 2×2 拼图暗示数量，我们的组可能只有 1 本，需要明说。
「更新」角标 右上红色「更新」，有新章节时出现 暂不做，位置留给「在读 N」 我们没有「上次检查更新时间」这个数据（Book 里只有 addedAt / lastOpenedAt），做「更新」要新增字段 + 全书源定时探测，是另一个功能。草案先用「在读 N」这个现成数据。
分组 chips 无（分组就是卡片） 删掉 现在的「全部书籍 / 小说 / 历史」chips 行与组卡重复。分组筛选功能不丢——组卡本身就是筛选入口，还多了一屏可见的分组数。
继续阅读卡 无（顶部 tab「阅读」承担） 保留，只在「默认」页顶部 这是我们现在最有用的入口（遮天 继续阅读），微信读书用底部「阅读」tab 承担同一职责。建议保留，但收进默认页，进组后不出现。
在读/已读筛选 「进度」tab 「进度」tab（按进度排序，在读置顶） 现在是筛选（只看在读），草案改成排序（在读排前面）。想只看在读可以再议，见第四节问题 2。
列表/网格切换 无 保留在组内层右上「▤」 组内书少，列表模式的价值主要在组内。分组层固定拼图卡。
底部导航 阅读 / 书架 / 有声书 / 我 不动：书架 / 发现 / 书源 / 我的 我们没有有声书；书源是 read-pilot 的核心能力，必须留。

四、需要你拍板的三件事

问题 1
没有分组的书怎么办？
现在大部分用户的书写进来是没有分组的（导入 TXT、加书架都不带分组）。三个选法：
A 自动生成一张「未分组」卡（草案默认，最像微信读书）
B 没有分组时退回现在的平铺书籍网格（零分组用户无感）
C 强制要求先建分组
问题 2
「在读 / 已读」筛选还留吗？
草案把它并成「进度」tab 只做排序。如果你平时会点「只看在读」，那就把 在读/已读 做成标题行右侧的一个筛选图标（像现在书源页的分组筛选那样），不占一行。
问题 3
组卡的右上角标显示什么？
微信读书是「更新」，我们没有更新数据。可选：A「在读 N」（草案）；B 不显示，保持干净；C 显示未读数。
选 A/C 都是现成数据，选「更新」要另做功能。
