## 逐项复核

1. **首屏问题**：书架回答“现在读哪本”，继续阅读和书封是主体。不是阅读统计仪表盘，没有伪造时长、好友或评分。
2. **布局边界**：同一页面的标题、搜索和书架共用左右边线；手机第一排三本封面全部处于底部导航上方，正文采用独立行长限制。
3. **色彩**：主界面以白与浅灰为主，蓝色用于操作；书封有固定的低饱和对象色。未使用背景渐变、玻璃模糊或装饰性 KPI 图标。
4. **真实数据**：书籍数量、在读/已读、缓存章节和笔记数量由本地记录计算。首次没有假进度；真实验收操作产生的进度只在测试浏览器中存在。
5. **空与错误状态**：验证了搜索无结果、禁止脚本书源、断开的书源和未缓存正文的错误。错误保留重试路径；书源离线不影响缓存章节。
6. **图表与标记**：没有无意义图表。公版“节选”与缓存状态明确标注，不将样本冒充全本或在线书库。
7. **手机**：侧栏折叠为四项底部导航；文字和主要操作保留，书架与长文均无横向溢出。

## 验收方法的边界

Flutter Web 使用 CanvasKit。CSS/DOM 风格检查器不能代表实际绘制的字号、配色与布局，因此没有声称 `inspect.mjs` 得到“0 FAIL”。本次以 Flutter 组件测试、语义定位、真实鼠标操作、实际截图及溢出测量为依据。

Flutter 的语义层可能有透明的命中代理。自动化在确认控件的语义与当前边界后使用真实鼠标点击，而不是通过修改 DOM 或强行注入业务状态让测试通过。移动视口后重新加载，以避免测试浏览器切换设备像素比时的旧画布尺寸影响截图。

原生 Android/iOS/Windows 的视觉与触摸交互尚未做设备验收，不能将这些 Web 截图视为原生端验收结果。
